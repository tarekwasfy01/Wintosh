## Execution boundary

The supported architecture target is the native Windows adapter and runner;
WSL is optional reference/backend infrastructure, not a runtime prerequisite.
On the current host, direct WSL probing returns `Wsl/E_ACCESSDENIED`, so no
WSL-backed Darling execution is claimed or required for the native smoke-test
suite.

The native `wintosh.exe` Release target was built and verified with
`--help`, `--version` (`Wintosh 0.1.1`), and `--diagnose-host`. The host
diagnostic confirms the current x86_64 native target and the fail-closed
boundaries for i386/ARM64 on this host. A repository-owned synthetic x86_64
Mach-O fixture is now bundled, so `--inspect` and native execution are proven
for that controlled fixture; arbitrary macOS binaries remain unclaimed.

The Darwin process-termination export family now includes `_abort`/`abort` in
addition to `exit` and `_exit`. The Windows adapter terminates the current
process directly with the conventional SIGABRT status rather than unwinding
through guest frames; symbol availability is covered by `host_api_smoke`.

The startup/runtime query family now exports
`NSVersionOfRunTimeLibrary` and `NSVersionOfLinkTimeLibrary`. They report the
version-1 Wintosh bridge for `libSystem`/`libobjc` spellings and return `-1`
for libraries that are not bundled; they do not claim Apple binary-version
compatibility.

The classic dyld symbol-query family now also exports
`NSLookupSymbolInImage` and `NSAddressOfSymbol`.  The dynamic-loader smoke
loads a repository-owned Mach-O, locates its image header through the dyld
image list, and verifies that the image lookup returns the same address as
`dlsym`.  Wintosh represents the opaque `NSSymbol` token by that resolved
address; complete Apple symbol-option and lifetime semantics remain open.

The legacy dyld family now additionally covers module lookup/binding
(`NSLookupSymbolInModule`, `NSLookupAndBindSymbol`, and the hint/predicate
variants), image/library addition, and module metadata.  The deprecated
Object-File-Image subset has a Wintosh-owned token with file creation,
definition-count/name queries, symbol-definition checks, and bounded
`NSLinkModule`/`NSUnLinkModule` projection.  These paths are verified against
the repository-owned dynamic Mach-O fixture and use the existing registry for
reference counting.  In-memory object images, deferred bundle linking,
Apple's unload flags, and legacy initializer/error-handler semantics remain
unimplemented; these are deliberately documented boundaries rather than
silent fallbacks.

The runner also provides `--init-prefix <directory>`, which creates the
documented Darwin directory layout (`System/Library/Frameworks`, `usr/lib`,
and the relevant `Library` data roots) without downloading or fabricating
Apple libraries. See [MACOS-DIRECTORY-MAP.md](MACOS-DIRECTORY-MAP.md). The
repository-owned x86_64 fixture now proves `--inspect` and
native execution; real system dylibs and frameworks are still not bundled.

The runtime-provider fixture now verifies a three-image provider chain:
`RuntimeClient.macho` resolves and calls `_libSystemInit` from the repository's
own `libSystem.B.dylib`, which itself depends on the repository's own
`libsystem_platform.dylib`. This proves the native provider graph and call
path, but these files are test providers rather than Apple's system libraries.

## What is included in a source release

Include the Windows port source, all documentation, and the `licenses`
directory. Do not vendor the large upstream reference checkouts; link to the
original repositories and keep every applicable license and notice here. A
source release must not silently replace a third-party license with the
Wintosh-original MIT notice.

## What is not claimed

This manifest proves that the current files are present in this workspace. It
does not prove that all 150 Darling external components are license-cleared,
that the NTFS-incompatible Heimdal checkout is complete, that the global build
passes, or that arbitrary macOS applications run on Windows. Those boundaries
remain in [STATUS.md](STATUS.md) and [RELEASE-CHECKLIST.md](RELEASE-CHECKLIST.md).

## Latest verified native adapter families

The current local branch additionally contains a prefix-relative Preferences
adapter. Its tested subset includes application and suite plist domains,
registration and argument values, managed/effective read-only views,
cross-process named-event wakeups, FIFO key events in a `.events` sidecar,
orphaned `.tmp` plist recovery, and reentrant observer snapshots including
observer self-removal and observer addition during delivery. The pthread
synchronization smoke also verifies priority-ceiling attribute propagation and
old-value return behavior. These are Wintosh-original Windows adapters with
their provenance recorded in `PRIMITIVE-MATRIX.csv`; they do not claim the
complete Foundation, notification-center, scheduler, or Objective-C ABI.

Preferences observer delivery now also defers store destruction requested from
inside an observer until the callback snapshot and the active mutation lock
are finished. The callback-destruction smoke covers this lifetime boundary;
the full NSUserDefaults ABI and cross-process observer lifecycle remain open.

External preference reloads now diff the previous and current domain and
deliver changed and removed keys to the local observer snapshot during
`poll_external`/`wait_external`. The cross-process smoke verifies FIFO order,
reloaded values, and callback delivery; native Darwin notification-center
semantics remain outside this adapter.

Preference loading now compares the main plist and orphaned `.tmp` by write
time and selects the newer valid source, covering recovery after an interrupted
replacement even when an older main plist still exists.

The external `.events` queue is now serialized by a named Windows mutex for
both append and drain operations, so concurrent preference writers and readers
cannot interleave truncation or consume partial records. This closes the local
queue atomicity boundary, but not multi-file transactional journaling.

The CoreFoundation collection family now snapshots and retains array, dictionary,
and set values while applier callbacks run. Callbacks may remove or replace
entries from the mutable collection without invalidating the active iteration;
a dedicated mutation test covers all three collection types. This is still
collection-ABI coverage, not the complete CoreFoundation object model.

The same scalar family now rejects non-finite and out-of-range floating-point
to-int64 conversions without invoking undefined behavior, and gives NaN number
comparisons a deterministic unordered result.

RunLoop mode and one-shot timer durations now reject NaN and infinite values
before entering `std::chrono`; the CoreFoundation smoke covers both invalid
mode and timer inputs. Real CFRunLoop sources, modes, cancellation, and timer
invalidations remain outside this minimal adapter.

The Objective-C bridge now covers `objc_msgSendSuper` with a boolean argument
(`B@:B`) in addition to the existing direct-send path; the registry smoke
executes a Root-class super method to prove the argument promotion and return
value boundary. General variadic Objective-C dispatch and aggregate signatures
remain incomplete.

The same Super bridge now covers void integer and void int64 arguments
(`v@:i` and `v@:q`), with the smoke invoking both Root-class methods. This
extends fixed-arity ABI coverage only; it does not provide arbitrary variadic
or aggregate Objective-C dispatch.

The Super bridge now has separate ABI-safe typed entry points for the complete
currently supported scalar floating-point arities: `d@:`/`d@:d`/`d@:dd` and
`f@:`/`f@:f`/`f@:ff`. These return `double` or `float` directly instead of
forcing a floating-point result through the untyped `id objc_msgSendSuper`
signature; the Objective-C smoke exercises all six Root-class paths. This is
still a fixed-signature bridge, not general Apple variadic ABI support.

Unsigned integer Super dispatch now also has typed `Q@:`/`Q@:Q` and
`I@:`/`I@:I` entry points for 64-bit and 32-bit results. The smoke covers
zero- and one-argument Root-class methods; the untyped Super entry point is
not used for these scalar returns.

The integer Super family now also includes tested two-argument typed forms
`q@:qq`, `Q@:QQ`, and `I@:II`, all returning native scalar values directly.

The CGRect-like aggregate family now has typed Super entry points for zero- and

unsupported.

The same CGRect family also supports a typed void Super call carrying one

Object-returning Super dispatch now also has typed zero-, one-, and
